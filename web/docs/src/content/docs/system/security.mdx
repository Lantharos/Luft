## A signed startup

Everything that starts a Luft computer is signed, from the firmware to the last system file:

1. The firmware starts Fedora's boot loader, signed by Microsoft.
2. That starts Luft's boot menu, signed with Luft's key.
3. The boot menu starts Luft's startup image, the kernel and everything it needs in one signed file.
4. The startup image names the exact system it belongs to, and the system is only mounted if every file matches.

So nothing between pressing the power button and your desktop can be changed without Secure Boot noticing. Your computer trusts Luft's key once you confirm it on [the blue screen](/start/first-start/#the-blue-screen).

Secure Boot stays optional. With it off, Luft still starts, and nothing is locked down against you as the computer's owner: drivers you build yourself load, but games with anti-cheat aren't available.

## Device encryption

Install Luft asks whether to encrypt Luft right after you choose where it goes, and shows its recovery key: 12 words. Save it to a USB drive, print it, or write it down; when you write it down, Luft asks for three of the words to check you have them. Keep it somewhere other than this computer. If you skipped it, Settings, under Security, **Device encryption**, can encrypt Luft later with **Turn on**. Your files stay where they are: Luft makes room, starts encrypting when you restart, and then encrypts in the background while you use the computer. Keep it plugged in until it's done. Encryption can't be turned off again.

With a TPM, the disk unlocks by itself when the computer started the way it should. Install Luft links it before the first start; if the computer measures its startup differently than expected, the first start asks once for the recovery key you just saved, and unlocks by itself from then on. An optional PIN of 6 to 20 digits adds something only you know. Without a TPM, a passphrase is asked at every start.

The TPM keeps unlocking through Luft's updates and ordinary firmware updates. If Secure Boot is turned off or its keys change, the computer asks for the recovery key and says why. When the keys changed, Settings then says the computer starts differently now: if you made the change, confirm it with your password and the disk unlocks by itself again, and until then every start asks for the recovery key. With Secure Boot off, Settings offers to link the TPM again. Settings can show the recovery key again, after your password, and replace it.

### Other drives

[Disks](/apps/disks/) can encrypt other drives in place, with a recovery key and an optional passphrase. **Unlock automatically on this computer** opens them without asking when Luft itself is encrypted, like BitLocker's automatic unlock.

## Luft Keyring

Your passwords, sign-in tokens and keys live in Luft Keyring, encrypted in one file. Signing in unlocks it, with your password or a fingerprint, and it locks with the screen if you like. [Keyring and passkeys](/files/keyring-and-passkeys/) explains how apps get access.

## USB protection

While the screen is locked, and at the login screen, new USB devices wait until you unlock. Keyboards, mice, security keys and hubs connect right away, but a gadget that also poses as a network adapter or a drive only gets its keyboard part. When you unlock, everything that waited connects and a notification names it.

Devices already connected keep working. Turning this off in Settings needs an administrator.

## Home and public networks

Every Wi-Fi and wired network is either a home network or a public one. On a home network, your other devices can find this computer and connect to it, so casting to a Chromecast, Spotify Connect, games on the local network, Steam streaming and sharing files work without setting anything up. On a public network, like in a café, hotel or airport, nothing on the network can connect to this computer; only the answers to its own connections come in.

The first time Luft starts, it asks what kind of network you're on, with Home picked already. After that, a new network counts as public until you choose, and a notification asks. You can change any network in Settings, under Network → Firewall.

Even on a home network, the ports up to 1024, which belong to system services such as a web or file server, stay closed until you open them there. Opening one needs an administrator. Tailscale, and the virtual machines, containers and Android apps running on this computer, keep working on either kind of network.

## Games with anti-cheat

Easy Anti-Cheat for Linux and others like it only let a game run when the computer can show it started the way its maker intended. Luft meets each of Epic's requirements by default: a signed kernel and drivers, a TPM, Secure Boot with well-known keys only, a measured startup, the IOMMU, a locked-down kernel, and kexec turned off.

Settings says **Ready for games with anti-cheat**, or the first thing missing, such as Secure Boot being off. If other keys were added to the boot loader in the past, Settings can remove them, after you confirm on the blue screen at the next restart.

Epic's list of well-known keys doesn't include Luft's key, and nothing on your computer changes that; games that check for it start working once Epic adds it.

Hibernation isn't available while the kernel is locked down. Sleep works as usual.

## Further reading

[Security model](/reference/security/) and [Boot and recovery](/reference/boot/) go into the details: which keys sign what, what the TPM measures, and what each protection does and doesn't guard against.

From the command line, `sudo trustctl status` shows Secure Boot, the keys, the TPM and the disk, and `sudo trustctl anti-cheat` lists each anti-cheat requirement.
