## A signed startup

Everything that starts a Luft computer is signed, from the firmware to the last system file:

1. The firmware starts Fedora's boot loader, signed by Microsoft.
2. That starts Luft's boot menu, signed with Luft's key.
3. The boot menu starts Luft's startup image, the kernel and everything it needs in one signed file.
4. The startup image names the exact system it belongs to, and the system is only mounted if every file matches.

So nothing between pressing the power button and your desktop can be changed without Secure Boot noticing. Your computer trusts Luft's key once you confirm it on [the blue screen](/start/first-start/#the-blue-screen).

Secure Boot stays optional. With it off, Luft still starts, and nothing is locked down against you as the computer's owner: drivers you build yourself load, but games with anti-cheat aren't available.

## Device encryption

Install Luft asks whether to encrypt Luft right after you choose where it goes, and shows its recovery key: 12 words. Save it to a USB drive, print it, or write it down; when you write it down, Luft asks for three of the words to check you have them. Keep it somewhere other than this computer. If you skipped it, Settings, under Security, **Device encryption**, can encrypt Luft later with **Turn on**. Your files stay where they are: Luft makes room, starts encrypting when you restart, and then encrypts in the background while you use the computer. Keep it plugged in until it's done. Encryption can't be turned off again.

With a TPM, the disk unlocks by itself when the computer started the way it should. Install Luft links it before the first start; if the computer measures its startup differently than expected, the first start asks once for the recovery key you just saved, and unlocks by itself from then on. An optional PIN of 6 to 20 digits adds something only you know. Without a TPM, a passphrase is asked at every start.

The TPM keeps unlocking through Luft's updates and ordinary firmware updates. If Secure Boot is turned off or its keys change, the computer asks for the recovery key and says why. When the keys changed, Settings then says the computer starts differently now: if you made the change, confirm it with your password and the disk unlocks by itself again, and until then every start asks for the recovery key. With Secure Boot off, the TPM doesn't unlock the disk, because nothing then checks what starts the computer: Settings says so, and every start asks for your passphrase or recovery key until Secure Boot is on again. Settings can show the recovery key again, after your password, and replace it.

### Other drives

[Disks](/apps/disks/) can encrypt other drives in place, with a recovery key and an optional passphrase. **Unlock automatically on this computer** opens them without asking when Luft itself is encrypted, like BitLocker's automatic unlock.

## Luft Keyring

Your passwords, sign-in tokens and keys live in Luft Keyring, encrypted in one file. Signing in unlocks it, with your password or a fingerprint, and it locks with the screen if you like. [Keyring and passkeys](/files/keyring-and-passkeys/) explains how apps get access.

## Signing in automatically

Settings, under Accounts → Login screen, can sign one person in at startup without a password. It's off unless you turn it on. When nothing asks for a password while the computer starts, because the disk isn't encrypted or the TPM unlocks it without a PIN, Settings asks you to confirm first: anyone who can switch the computer on then reaches that person's desktop and files without typing anything. Luft Keyring stays locked until the password is typed, and the lock screen still asks for it after the computer sleeps or locks, as long as **Lock the screen when it turns off** is on under Privacy. Restarting the computer gets past the lock screen, though.

## USB protection

While the screen is locked, and at the login screen, new USB devices wait until you unlock. Plain keyboards, mice and hubs connect right away, so you can always type your password, but a gadget that also poses as a network adapter or a drive only gets its keyboard part. Drives, network adapters, security keys and other special devices wait. When you unlock, everything that waited connects and a notification names it.

Devices already connected keep working. Turning this off in Settings needs an administrator.

## Home and public networks

Every Wi-Fi and wired network is either a home network or a public one. Other devices on a network can only connect to the apps you let them. The first time an app waits for connections from other devices, like a game hosting a match, Steam streaming, Spotify Connect or a file sharing app, Luft asks whether to allow it. Allowing lets your phones, computers and speakers on home networks connect to that app, and Luft asks for your password or fingerprint first, so no program can allow itself behind your back. If you're not sure, choose Don't allow: the app keeps working on this computer, and you can change your mind later. Your answer is remembered for that app, for your account only.

On a public network, like in a café, hotel or airport, no app can be reached unless you allowed it there too, which only Settings offers. Your computer doesn't answer ping there and doesn't announce itself to other devices, so they don't see its name. Printers, AirPlay and Chromecast are found on home networks.

The first time Luft starts, it asks what kind of network you're on, with Home picked already. After that, a new network counts as public until you choose, and a notification asks. You can change any network, and what each app may do, in Settings, under Network → Firewall: Home networks, All networks or Not allowed. Making a network a home network asks for your password or fingerprint, and allowing an app on all networks needs an administrator. Making things stricter never asks.

Programs you start in Tern, such as a web server you're working on, are asked about by their name, like python3. Services that run without an app, such as a file server, are never asked about and stay closed until you open their port on that page, which needs an administrator. SSH has a page of its own, [Remote login](#remote-login). Extensions that take connections from your network were allowed when you installed them, on home networks. Tailscale, and the virtual machines, containers and Android apps running on this computer, keep working on either kind of network. Devices in your tailnet, and those virtual machines and containers, reach the same apps and ports as devices on a home network, and nothing else on this computer.

## Remote login

Remote login lets you sign in to this computer from another device with SSH, to use its terminal and files from your laptop or phone. It's off until you turn it on in Settings, under Security → Remote login, and while it's off, nothing on the computer listens for SSH at all.

Turning it on needs an administrator, because anyone with a key you add can then control the computer as you: open your files, run programs and change what you can change. At first only your account can sign in, only from devices on home networks, and only with a key, never a password or as root.

1. On the device you'll connect from, make a key if it has none, with `ssh-keygen -t ed25519`.
2. In Settings, choose **Add a key** and paste its public key, or choose the `.pub` file, such as `id_ed25519.pub`. Never add the file without `.pub`: that's the private key, and it stays on the other device.
3. Connect with the command the page shows, such as `ssh anna@annas-laptop.local`, or with one of the addresses it lists.

The first time a device connects, SSH shows a fingerprint and asks whether to trust it. Compare it with the ones under **This computer's keys**. If it doesn't match any of them, something between the two devices is pretending to be your computer, so don't go on.

Every time someone signs in over SSH, a notification says so, with the account and the other device's address, even during Do Not Disturb. **Signed in now** lists who's connected, and **Disconnect** ends a connection right away. Turning remote login off disconnects everyone.

The page also chooses which accounts can sign in. Each one adds its own keys while signed in to it. Two more switches are there for when they're really needed, each with a warning and an administrator's password:

- **Allow passwords** lets accounts sign in with their password as well. Anyone who knows or guesses it can then get in, so it's only for a device that can't use a key.
- **Also on public networks** lets devices on public networks, like in a café or hotel, connect as well. They can then see that the computer takes SSH connections.

Luft slows down anyone who keeps trying: after a few failed sign-ins from one address, that address has to wait before it can try again, up to an hour.

## Developer tools

**Developer tools**, under Security, is for people who build apps for Luft, and stays off otherwise. Turning it on needs an administrator. It lets developer tools such as `peek` see and control your windows, and it opens the text consoles: pressing Ctrl+Alt+F3 or the keys next to it then shows a text login, as on other Linux systems, where anyone at the computer can sign in with an account's password without the login screen. While it's off, those keys show an empty screen, and Ctrl+Alt+F7 returns to where you were. Turning it off closes the text consoles that are open. It also lets you run an extension nobody reviewed inside the desktop, after asking for your password, and turning it off puts every such extension back in its sandbox ([Extensions](/personalize/extensions/#extensions-nobody-reviewed)). [Rescue](/system/recovery/#rescue) keeps working either way.

## Games with anti-cheat

Easy Anti-Cheat for Linux and others like it only let a game run when the computer can show it started the way its maker intended. Luft meets each of Epic's requirements by default: a signed kernel and drivers, a TPM, Secure Boot with well-known keys only, a measured startup, the IOMMU, a locked-down kernel, and kexec turned off.

Settings says **Ready for games with anti-cheat**, or the first thing missing, such as Secure Boot being off. If other keys were added to the boot loader in the past, Settings can remove them, after you confirm on the blue screen at the next restart.

Epic's list of well-known keys doesn't include Luft's key, and nothing on your computer changes that; games that check for it start working once Epic adds it.

Hibernation isn't available while the kernel is locked down. Sleep works as usual.

## From the command line

`sudo trustctl status` shows Secure Boot, the keys, the TPM and the disk, and `sudo trustctl anti-cheat` lists each anti-cheat requirement. [Keys, signatures and the build](/security/keys/) and the pages after it explain how each protection works and what it doesn't guard against.
